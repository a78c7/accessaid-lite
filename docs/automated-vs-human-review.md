# Automated Vs Human Review

AccessAid Lite is a preliminary automated check. It helps teams find common static issues, but it is not a full WCAG audit and does not provide legal or medical advice.

| Review type | Good for | Cannot determine | Who should do it |
| --- | --- | --- | --- |
| Automated preliminary check | Common static issues such as missing title, missing alt, skipped headings, generic links, and unlabeled controls | Real usability, legal compliance, screen reader behavior, focus order, contrast in context, dynamic states | Maintainers, volunteers, developers |
| Human accessibility review | Practical barriers, task flow, clarity, assistive technology sanity checks, real user needs | Every WCAG detail unless the reviewer is trained for that scope | Users, reviewers, accessibility-aware staff |
| Full audit | Deeper WCAG assessment, structured evidence, broader risk review | Ongoing maintenance alone | Qualified accessibility professional |

Use AccessAid Lite as a first pass, then involve human reviewers before making accessibility claims.

## Why Automated Findings Need Context

Static checks can find common patterns, but they cannot understand the full page purpose or user task.

Possible false-positive or context-dependent cases include:

- Empty `alt=""` on an image that is decorative and should stay empty.
- Generic link text that may be clarified by surrounding visible text.
- Missing landmarks on a very short single-purpose page.
- Heading structures generated by a content system.
- Custom controls that look risky in static HTML but are made keyboard-operable by code that the tool does not execute.

Treat blockers and warnings as triage signals. They may help prioritize review, but they do not prove the page is inaccessible, accessible, compliant, or non-compliant.

## Human Review Should Confirm

- The main user task can be completed with a keyboard.
- Focus order and visible focus are understandable.
- Screen reader output makes sense for the page purpose.
- Images, icons, and charts have appropriate alternatives.
- Form labels, instructions, and errors are clear.
- Color, zoom, reflow, and mobile behavior work in real use.
- Any severity override reflects a documented review decision.
